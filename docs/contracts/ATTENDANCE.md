# Contract — Attendance (teacher mode, scheduling, rotating QR)

Owner module: `backend/src/modules/attendance/`. All routes are mounted at `/api/v1/attendance`
and require `verifyJWT` (sets `req.user`). Times are stored in UTC; the college time zone is
`APP_TIMEZONE` (default `Asia/Kolkata`) and is used for timetables, "tomorrow 10am" parsing and
working hours. Responses use the existing envelope `new Apiresponse(status, data, message)` →
`{ statusCode, data, message, success }`; errors use `ApiError(status, message, errors)` →
`{ success:false, message, errors, data:null }`. Every error that the UI branches on carries a
machine code in `errors[0].code` (listed below).

## Roles
- `teacher` — owns courses, schedules sessions, presents the QR, marks attendance manually.
- `student` — joins/enrolled in courses, scans, sees own stats.
- `tpo` / `admin` — read-only access to every course/session report (department oversight).

## Rotating QR — security rules (must hold)
1. When a session goes live the server generates `nonce = crypto.randomBytes(16).toString("base64url")`, `version = 1`, `expiresAt = now + qrRotationSeconds`.
2. The QR encodes the deep link `${FRONTEND_URL}/attend?s=<sessionId>&t=<nonce>&v=<version>`. The token is the nonce; it is single-use.
3. `POST /attendance/scan` consumes the token with ONE atomic `findOneAndUpdate`:
   filter `{_id: sessionId, status: "live", "qr.nonce": token, "qr.expiresAt": {$gt: now}}`,
   update `$set` a brand-new nonce, `qr.version: v+1`, new `issuedAt/expiresAt`.
   If no document matches → the token is stale/used/expired → `410 TOKEN_EXPIRED` (or `400 INVALID_TOKEN` when the session id is unknown, `409 SESSION_NOT_LIVE` when not live). Two concurrent scans of the same token: exactly one wins.
4. All other checks (enrolled, already-marked, device-reuse, geo) run BEFORE consuming the token so a rejected scan does not burn the teacher's current QR. Order: session exists & live → student enrolled (`403 NOT_ENROLLED`) → not already marked (`409 ALREADY_MARKED`) → device not used for another student in this session (`403 DEVICE_ALREADY_USED`) → geo within `radius + min(accuracy, 100)` when `requireGeo` (`403 OUT_OF_RANGE`; `400 LOCATION_REQUIRED` if missing) → consume token atomically → insert record (duplicate-key race → `409 ALREADY_MARKED`).
5. After every successful scan the new token is pushed to the presenter room (`attendance:qr`) together with `attendance:marked`. Independently, a time-based rotation runs: while any session is live, a server ticker (every 1s, cheap query on `status: "live", "qr.expiresAt": {$lte: now}`) rotates expired tokens and pushes them. So a photographed QR dies after one use OR `qrRotationSeconds`, whichever is first.
6. Status is `late` when `now > startsAt + lateAfterMinutes`, otherwise `present`.
7. Rate limit: max 10 scan attempts / minute / user (in-memory sliding window) → `429 TOO_MANY_ATTEMPTS`.

Error codes (`errors[0].code`): `INVALID_TOKEN`, `TOKEN_EXPIRED`, `SESSION_NOT_LIVE`, `NOT_ENROLLED`, `ALREADY_MARKED`, `DEVICE_ALREADY_USED`, `OUT_OF_RANGE`, `LOCATION_REQUIRED`, `TOO_MANY_ATTEMPTS`, `SCHEDULE_CONFLICT`, `NO_FREE_SLOT`, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION`.

## Scheduling rules
- Manual create/reschedule rejects overlaps with the same teacher's or the same course's non-cancelled sessions → `409 SCHEDULE_CONFLICT` with `errors[0].conflicts: [{sessionId, course, startsAt, endsAt}]`.
- Auto-schedule (`POST /sessions/auto`): search from `earliest` (default: now + 1h, rounded up to 15 min) to `latest` (default: +7 days) inside working hours `WORK_DAY_START`–`WORK_DAY_END` (default 09:00–17:00, college TZ) on `WORK_DAYS` (default Mon–Sat), 15-minute grid, avoiding the teacher's sessions, the course's sessions AND sessions of other courses that share ≥1 enrolled student. Optional `preferredDays: [0-6]`, `preferredStart/End: "HH:mm"`. Picks the earliest slot; `409 NO_FREE_SLOT` when none.
- Timetable materialisation: for every active course with a timetable, create `source: "timetable"` sessions for the next `settings.autoGenerateDays` days (idempotent via the unique index). Runs at boot, every 6 hours, and on `POST /courses/:id/generate`. One digest notification per student per run ("3 classes scheduled this week for CS301").
- `when` strings: endpoints that accept `when` (used by AI tools) parse with `chrono-node` in `APP_TIMEZONE` (`forwardDate: true`), e.g. "tomorrow 10am", "next monday 2:30 pm". ISO strings are accepted as-is.
- Background jobs (registered through `core/scheduler.js`, disabled when `NODE_ENV=test`):
  - every 60s: reminders for sessions starting in ≤ 15 min (`reminderSentAt` unset) → notify students + teacher.
  - every 60s: auto-end (finalise) live sessions whose `endsAt + autoEndGraceMinutes < now`.
  - Sessions that never went live stay `scheduled`; API responses flag them `isMissed: true` when `endsAt < now`. They do NOT count toward attendance totals.
  - every 1s while any session is live: time-based QR rotation (rule 5).
  - every 6h: timetable materialisation.

## Finalising a session (`end`, manual or auto)
Set `status: "ended"`, `endedAt`, invalidate QR (`qr.nonce` = random, `expiresAt` = now), insert `absent` (`method: "auto"`) records for every enrolled student without a record (bulk upsert), recompute `stats`, emit `attendance:session` to course students + teacher, then notify students whose course percentage dropped below `minAttendancePercent` ("Your attendance in CS301 is 68% — attend the next 4 classes to reach 75%").

## Percentages
`held = ended sessions of the course`; per student `attended = present + late`; `excused` removed from the denominator: `percent = attended / (held - excused) * 100` (0 sessions → `null`). `needToReach` = minimum future consecutive attended classes to reach `minAttendancePercent`; `canSkip` = max classes they can miss and stay ≥ threshold. Status: `safe` (≥ threshold+5), `warning` (≥ threshold), `critical` (< threshold), `no-data`.

## REST API (`/api/v1/attendance`)
Courses
- `GET /courses` → teacher: own courses (+ `studentCount`, `nextSession`); student: enrolled courses (+ `summary` {attended, held, percent, status}); tpo/admin: all. `?status=archived` to include archived.
- `POST /courses` (teacher) body `{code, name, branch?, semester?, section?, passingYear?, academicYear?, room?, timetable?, settings?, autoEnroll?: boolean}` → `201 {course}`; `autoEnroll:true` enrolls matching students immediately.
- `GET /courses/:id` → teacher/tpo: `{course, students:[{_id,name,email,branch,ggsipuEnrollment, stats:{attended,held,percent,status}}], upcoming:[session]}`; enrolled student: `{course, summary, upcoming}`.
- `PATCH /courses/:id` (owner) same fields as create; `DELETE /courses/:id` (owner) → archives.
- `POST /courses/:id/students` (owner) `{emails?: string[], userIds?: string[]}` → `{added: n, notFound: [emails]}`; `DELETE /courses/:id/students/:studentId`.
- `POST /courses/:id/auto-enroll` (owner) → `{added}`.
- `POST /courses/:id/join-code` (owner) → regenerates `{joinCode}`.
- `POST /courses/join` (student) `{joinCode}` → `{course}`; `404 NOT_FOUND` for bad code.
- `POST /courses/:id/generate` (owner) `{days?}` → `{created: n, sessions:[...]}`.
- `GET /courses/:id/report` (owner/tpo) → `{course, held, students:[{student, attended, late, absent, excused, percent, status, needToReach}], defaulters:[...same, percent < threshold]}`.
- `POST /courses/:id/notify-defaulters` (owner) `{threshold?, message?}` → `{notified: n}`.

Sessions
- `GET /sessions?from&to&courseId&status` → role-scoped list (teacher: own; student: enrolled courses; tpo: all). Default window: today −1 day … +14 days. Each item includes `course {_id, code, name}`, `isMissed`, and for students `myRecord` (status or null).
- `POST /sessions` (teacher) `{courseId, startsAt | when, durationMinutes (default 60), room?, topic?, mode?}` → `201 {session}`; notifies enrolled students ("New class scheduled").
- `POST /sessions/auto` (teacher) `{courseId, durationMinutes?, earliest?, latest?, preferredDays?, preferredStart?, preferredEnd?, topic?, room?}` → `201 {session, reason: "Earliest free slot …"}`.
- `GET /sessions/:id` → teacher/tpo: `{session, course, roster:[{student, record|null}], stats}`; student: `{session, course, myRecord}`.
- `PATCH /sessions/:id` (owner, only `scheduled`) `{startsAt|when, durationMinutes, room, topic, mode}` → notifies "Class rescheduled".
- `POST /sessions/:id/cancel` (owner, `scheduled|live`) `{reason?}` → notifies "Class cancelled".
- `POST /sessions/:id/start` (owner; allowed from 30 min before `startsAt` until `endsAt`; `scheduled` → `live`) `{geo?: {lat,lng,accuracy}}` → `{session, qr: {token, version, expiresAt, url, rotationSeconds}}`; notifies students "Attendance is open for CS301 — scan the QR in class". Starting an already-live session just returns the current QR.
- `POST /sessions/:id/end` (owner) → `{session, stats}` (finalise rules above).
- `GET /sessions/:id/qr` (owner, live) → `{token, version, expiresAt, url, rotationSeconds}`. If the current token has already expired, it is rotated first (atomically, same rules as the ticker) so a presenter never displays a dead code even if the background ticker lags; `attendance:presenter:join` behaves the same way.
- `POST /sessions/:id/records` (owner) `{studentId, status: present|late|absent|excused, note?}` → upsert `method: "manual"` → `{record, stats}`; emits `attendance:marked`.
- `GET /sessions/:id/export.csv` (owner/tpo) → `text/csv` (Roll/Enrollment, Name, Email, Status, Method, Marked At (college TZ)).

Scanning & student views
- `POST /scan` (student) `{sessionId, token, deviceId, geo?: {lat,lng,accuracy}}` → `200 {status: "present"|"late", markedAt, session:{_id, topic, startsAt}, course:{_id, code, name}, summary:{attended, held, percent}}`.
- `GET /me/summary` (student) → `{courses:[{course, attended, late, absent, excused, held, percent, status, needToReach, canSkip}], overall:{attended, held, percent}}`.
- `GET /me/history?courseId&limit=50` (student) → `{records:[{session:{_id, topic, startsAt, endsAt}, course:{code,name}, status, method, markedAt}]}`.
- `GET /me/schedule?days=7` (student/teacher) → upcoming sessions (same shape as `GET /sessions`).

## Socket.IO (attendance)
Client → server (authenticated socket, see SOCKET contract):
- `attendance:presenter:join` `{sessionId}` ack `{ok, qr?, stats?, error?}` — only the owner teacher (or tpo/admin) of a LIVE session may join room `attendance:presenter:<sessionId>`.
- `attendance:presenter:leave` `{sessionId}`.
Server → client:
- `attendance:qr` → room `attendance:presenter:<id>`: `{sessionId, token, version, expiresAt, url, rotationSeconds}`.
- `attendance:marked` → presenter room: `{sessionId, record:{student:{_id,name,email,ggsipuEnrollment}, status, method, markedAt, flags}, stats}`.
- `attendance:session` → `user:<id>` rooms of the teacher + enrolled students: `{session}` on start / end / cancel / reschedule.
- The scanning student additionally receives `attendance:confirmed` on `user:<id>`: `{sessionId, status, course:{code,name}}`.
